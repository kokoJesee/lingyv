# 模块 8：业务存档 v2

2026-11-05。本机单用户比赛演示；明文 SQLite；不是生产数据保管或专业安全审核。

## 保存选择

仍使用 POST /sessions/{id}/archive。请求包含 expected_revision、可选 expected_archive_version；当会话含设备、自述、理解、相关操作记录或已进入心理流程时，必须另外传 save_business_data=true。前端以独立勾选框取得这次保存选择。缺少选择返回 archive_business_consent_required，不创建数据库。

v2 保存已完成对话、设备记录和已删除编号、自述、理解当前版本、来源依赖、支持路线及四类操作指纹。只保留历史 consent ID/version 作来源校验，不保存可恢复的用途授权。确认令牌、模型配置、任务、诊断事件与缓存回复不写入快照。原普通聊天 v1 存档继续可读写；保存新版本仍做会话和磁盘版本检查、4 MiB 限制与 SQLite 事务。

## 恢复

POST /archives/{id}/restore 在独立新内存中安装完整校验后的快照；当前进程已载入同一会话则拒绝覆盖。前端提供“打开已载入的会话”与恢复入口，不暗中覆盖更新内容。

- 设备记录可恢复，但 local_analysis/model_context 授权均为空；设备版本递增，需用户重新选择用途。
- 设备关联理解及其后代作废，需重新提出和核对；纯用户自述的当前确认理解可保留。
- 待确认理解、通用草稿换发令牌；旧操作编号变为 request_restored，不重新执行调用或重放缓存。
- 保存的支持路线保留；含业务对话的恢复会话保持支持流程，不能用普通聊天绕过来源过滤。
- 历史消息可回看，但新模型输入仍按理解、草稿和设备版本过滤旧助手回复。
- 已结束会话保持结束；未完成执行不会恢复运行。

## 删除与限制

DELETE /archives/{id}?expected_version=N 显式删除磁盘副本，当前内存仍保留。清空当前旅程只清内存，磁盘存档需单独删除。两处在页面上分别说明。

校验覆盖结构、交叉引用和版本一致性；本地文件没有签名，不能宣称可识别所有恶意篡改。无自动长期记忆、跨用户身份认证或云同步。保存/恢复是工程能力，不证明心理效果。
