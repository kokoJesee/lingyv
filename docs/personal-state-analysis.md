# 模块 4：个人基线与变化分析

状态：确定性计算、授权服务接缝、离线演示及测试已实现。无模型调用、诊断、安全路线判定或自动长期记忆写入。
入口：`app/services/state_analysis.py`；结果契约：`app/schemas/state_analysis.py`。

## 复现

在仓库根目录执行，JSON 默认打印到终端：

```bash
.venv/bin/python -B -m app.analysis_cli --scenario S02 --as-of 2026-11-04T00:00:00+08:00
```

可加 `--output data/mock-wearable/my-analysis.json` 写入新文件；父目录需存在，已有文件不会被覆盖。
该命令在临时内存会话生成虚构数据，显式授予该会话本地分析用途，再计算结果；不授予模型上下文用途，不使用已有用户会话。

本次 S02 实测：睡眠基线中位数 452 分钟，近期 348 分钟，差值 −104 分钟；入睡时点推迟 104 分钟。步数基线 6635、近期 6441，未达到询问阈值。这是模拟数据的计算结果，不代表真实用户效果。

## 计算规则

- 默认近期窗口为 as_of 所在分析时区日期之前的 3 个完整本地日；基线为紧邻此前的 14 个日历日。最少有效日数分别为 2、10，缺失时不向更早日期扩展。
- 只分析总睡眠、入睡时点、睡眠效率、静息心率、RMSSD、呼吸、皮肤温度偏差、步数、运动分钟共 9 项。SDNN 只保留兼容性数据；厂商评分不进入变化分析。
- 只纳入完整日、quality=valid、非空指标；已知 coverage 低于 0.8 不纳入。coverage 未提供时依赖 valid 标记，不伪造覆盖率。观测结束或导入时间晚于 as_of 的数据不纳入。
- 基线/近期均用中位数；delta=近期−基线。非零数值基线可计算 relative_delta；温度偏差和时点不算相对比例。
- 入睡用“相对醒来日本地午夜的墙上时间分钟数”：前一天 23:50 为 −10，醒来日 00:10 为 +10。避免普通钟表均值的跨午夜错误。该算法以记录的睡眠日归属正确为前提，不支持无日期的裸钟表时间。
- 分源键包含 provider、device、时区、模拟/真实标记、测量方法、聚合方法、采样窗口、算法版本、温度参考和部位。窗口内存在多个分源键、重复有效日或时区与分析配置不符时，保守返回 source_conflict，不猜测来源优先级。
- 切换来源后需在固定窗口中重新累积足够的同源有效日；不自动将旧设备作为新设备基线。完全不支持的新方法会表现为有效近期数据不足。
- 来源引用包含全部贡献日记录及其派生依赖的 ID/版本。依赖缺失/版本冲突拒绝输出；依赖质量不足或在 as_of 之后才可用也拒绝输出。当前记录级依赖采取保守策略，要求被引用记录内各指标都有效。

`AnalysisConfig` 可配置窗口、最少有效日数、coverage 和候选阈值；窗口有限，最少天数不能大于日历窗口。参数为比赛工程草案，不是临床界值。

## 输出与解释边界

`StateAnalysis` 包含会话、数据版本、用途、分析时区、算法版本、as_of、观察、逐指标状态和限制。分析 ID 由会话、输入内容、版本、配置、用途及时间确定；相同输入可复现。不同临时会话的 ID 不相同。

| 逐指标状态 | 含义 |
|---|---|
| ready | 当前指标可比较 |
| not_authorized | 当前用途未授权该核心指标 |
| no_data | 授权后仍没有窗口内可用候选记录，可能被来源权限过滤 |
| baseline_insufficient | 基线有效日不足 |
| recent_insufficient | 近期有效日不足 |
| quality_insufficient | 有数据但质量、完整性、时间可用性或依赖质量不足 |
| source_conflict | 来源/日期冲突，或证据引用无法验证 |

有任一可用观察时顶层 status=ready，其余指标的问题仍保留。没有可用观察时按未授权、来源冲突或数据不足报告，不输出“正常”或“无风险”。excluded_days 统计直接日级候选被排除的日期数，不包含派生来源中的子记录数。

只对以下两类变化生成 inquiry_candidate：

- 总睡眠绝对变化至少 60 分钟。
- 步数绝对变化至少 1500 且相对变化至少 30%；零基线无法计算比例，不触发该候选。

候选不是应立即打扰用户的指令，不触发心理风险或安全流程。睡眠/心血管/活动/其他夜间指标标 evidence_group，同源相关指标不相加成为综合分数。
服务返回全部可用核心观察供本地查询；每轮最多 3 组/6 项的模型摘要选择、用户偏好和重复提示抑制仍在后续 Agent 接入阶段实现。

## 授权与失效接缝

```python
analysis = await StateAnalysisService(wearable_service).analyze(
    session_id,
    as_of="2026-11-04T00:00:00+08:00",
    scope="local_analysis",  # model_context 必须单独获得该用途授权
    config=AnalysisConfig(timezone="Asia/Shanghai"),
)
```

服务在会话锁内获取模块 2 的用途过滤快照、读取授权、计算并再次验证版本。不修改会话、记录或授权，不保存结果。
底层 `analyze_changes` 是针对可信内部快照的纯计算函数，不能用来处理客户端自称已授权的数据。

`validate_result(session_id, result, scope=...)` 供后续提交方校验服务生成的结果：会话、数据版本和用途必须匹配，且会话有效。撤回、修订、删除或清空后原结果失效。本地分析结果不能直接当作云模型用途结果。
调用方须在同一会话锁内完成校验与使用，不能把外部 JSON 当成服务颁发的授权凭据。当前未接入实际模型上下文、缓存提交或小镇动作。
