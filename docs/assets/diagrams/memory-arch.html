长期记忆 · 模块内部架构 自下而上五层：触发 → 接入 → 服务 → 组件 → 存储；右侧是三条调用路径
1 · 触发源
画布确认（唯一自动提取点） 存进成长档案 身心便签 补一颗星 每轮对话 设置页操作 从存档恢复 评测（只读）
↓ 写：确认/便签/补记|↑ 读：每轮对话|↓ 删：设置页
2 · 接入层（薄，只做校验与转发）
POST /memories 手写 GET /memories 列表 PATCH /memories/{id} 改（带 revision） POST /memories/{id}/confirm DELETE /memories/{id} POST /sessions/{id}/memories/propose GET /memories/export GET /records 只读档案 501：import / merge / summarize
↓ 调用用例
3 · 服务层 MemoryService（五个用例，别的模块只认这层）
propose_from_canvas() confirm(memory_id, revision) select(session, topic, k≤5) delete(memory_id) export(format) 预留：import / merge / summarize
↓ 内部编排
4 · 组件层（六件事，各自独立可测）
提取器 Extractor写 读「本轮对话 + 刚确认的画布」，产出 0–3 条候选（kind / summary / text / importance / why）。输出必须过 schema，失败返回空，不猜。
写入裁决 Adjudicator写 与已有条目比对，决定 ADD / UPDATE / DELETE / NOOP；事实类做矛盾合并，偏好类只判重。
守卫 Guards全链路 四道闸：extract（安全路线不提取）、inject（恢复后敏感项不注入）、display（不进开场提示）、export（用户主动才导出）。
选择器 Selector读 过滤（已确认/未过期/未删）→ 打分（最近用过 + 重要度 + 话题）→ 取前 k → 生成摘要块；不相关的返回空。
依赖回写 DependencyWriter删 把「本轮用了哪几条 + 版本」写进 TurnDependencies.memory_refs；删除时据此剪掉旧回复与缓存。
导出器 Exporter导出 markdown（人可读、能带走）/ JSON（可再导入）。导出不含墓碑与内部版本字段。
↓ 持久化
5 · 存储层（一个文件，两张表）
memory_items · L2 条目 + 版本 + 时间窗（valid_from/to）+ 使用计数 + 墓碑。索引：(status,kind,last_used_at)、(status,valid_to)。
confirmed_records · L1 用户保存的档案记录（画布/卡片/便签/补记），按天索引，按需调取。
config / feature flags 上限（500 条 / 200 字）、k、decay、守卫开关、预留能力开闭。
↓ 依赖
6 · 外部依赖
data/memories.sqlite3（明文） 模型调用（经共享 CallScheduler，有超时与排队） 会话状态 SessionRecord（内存） 档案服务（读 L1）

写路径

画布确认 → API → extract 守卫 → 提取器 → 裁决 → 用户勾选 → 存储
安全路线时在第 3 步直接返回空

读路径

每轮 → 选择器 → 过滤 → 打分 → 取前 k → 摘要块 → 上下文 → 写回依赖
没有相关条目就返回空，不报错

删路径

设置页删 → 清正文留墓碑 → 找依赖 → 旧回复与缓存失效 → 30 天后清墓碑

三条内部原则

窄接口：只有服务层对外；组件层不许被别的模块直接 import。
乐观锁：所有写操作带 revision，冲突返回 409。
失败不阻塞对话：记忆读写异常 → 本轮不带记忆继续，记一条事件。
