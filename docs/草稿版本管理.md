# 通用草稿版本管理 V0.1

本模块已完成独立开发。内容使用 title/items 通用示例，不定义心理字段、评分或风险规则。
草稿仍只保存在当前进程内存中，没有自动保存到磁盘、长期记忆或公共案例库。

## 终端体验

在 PowerShell 中运行：

~~~powershell
Set-Location '<项目根目录>'
.\.venv\Scripts\python.exe -B -m app.cli --draft-demo
~~~

会依次展示创建、修改、拒绝旧版本确认、确认当前版本、修改后原确认失效、
清空草稿与缓存内容。这个演示不访问模型服务，也不消耗 API 额度。

手动操作：

~~~powershell
.\.venv\Scripts\python.exe -B -m app.cli --offline
~~~

依次输入：

~~~text
/draft-new 第一份草稿
/draft-edit 修改后的标题
/draft-confirm
/draft-edit 确认后再次修改
/draft-reject
/draft-list
/clear
/draft
/exit
~~~

/draft 和草稿编辑、确认、拒绝命令默认针对当前会话最新创建的草稿。
API 可以通过具体 draft_id 操作其他草稿。
在旧聊天终端中先输入 /exit，再重新运行，才能载入新增命令。

## 版本和状态

- 创建产生版本 1，状态 PROPOSED，返回确认凭据。
- 编辑、确认、拒绝每次成功都递增版本；读取和相同操作重放不递增。
- 编辑需要 expected_revision 与当前版本一致，否则返回 409 stale_revision。
- 确认还需要当前 confirmation_token；旧凭据返回 409 stale_confirmation。
- 确认后状态为 CONFIRMED，confirmed_revision 指向确认后的版本，凭据被消耗。
- 编辑已确认草稿后，状态恢复 PROPOSED，清除 confirmed_revision 并生成新凭据。
- 用户可以拒绝待确认草稿，或撤回已确认草稿。状态变为 REJECTED，旧确认被清除。
- 已拒绝草稿只读；需要继续时创建新草稿。
- 会话结束后拒绝新的草稿修改；清空时删除草稿及其操作结果缓存。
- 草稿确认与流程演示的确认相互独立，不会自动推进心理业务状态。

“确认”只表示用户确认了这份特定版本的草稿，不代表客观核实、专业审核或数据用途授权。

## API

先 POST /sessions 创建会话，再使用：

| 方法与路径 | 用途 |
|---|---|
| POST /sessions/{id}/drafts | 创建草稿 |
| GET /sessions/{id}/drafts | 当前会话的草稿列表 |
| GET /sessions/{id}/drafts/{draft_id} | 当前版本 |
| PUT /sessions/{id}/drafts/{draft_id} | 按预期版本替换内容 |
| POST /sessions/{id}/drafts/{draft_id}/confirm | 确认当前版本和凭据 |
| POST /sessions/{id}/drafts/{draft_id}/reject | 拒绝或撤回当前版本 |

创建请求示例：

~~~json
{"content": {"title": "通用草稿", "items": ["第一项"]}}
~~~

修改请求示例：

~~~json
{"expected_revision": 1, "content": {"title": "修改后", "items": ["第二项"]}}
~~~

确认请求包含 expected_revision 和读取结果中的 confirmation_token。
拒绝请求包含 expected_revision。

所有修改请求都可携带 operation_id。省略时自动创建新编号。
同一会话内相同编号、相同操作返回原结果；相同编号用于不同内容或动作返回 409。
失败结果也会重放，重新尝试使用新编号。重放返回的是原响应快照，
要查看草稿的最新版本，请使用 GET，不把旧响应当作当前状态。
清空后旧编号仅保留墓碑，不能恢复旧草稿或缓存正文。

草稿与聊天共享会话串行锁、生命周期屏障和操作记录数量预算；
草稿内容也受字符长度预算限制。日志只含动作、编号、版本和状态，不包含内容。

- 自动测试覆盖版本冲突、并发编辑、确认失效、撤回、操作重放、隔离、长度和操作上限。
