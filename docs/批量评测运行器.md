# 批量评测运行器 V0.1

现在可以用一条命令检查 Agent 的工程行为。此版本只运行虚构案例和模拟模型，不读取 .env，不调用 DeepSeek。

## 在终端查看

在 VS Code 终端执行：

~~~powershell
cd <项目根目录>
.\dev.ps1 -Mode eval
~~~

也可以直接执行：

~~~powershell
.\.venv\Scripts\python.exe -B -m app.evaluation
~~~

终端逐条显示案例编号、PASS/FAIL、模拟调用次数和耗时；结束后打印报告位置。
共享代码默认将报告保存在项目 reports/；个人目录可用 local.paths.json 配置。--output 可覆盖配置，每次新建目录并保留旧结果。

- report.md：适合打开阅读，显示通过情况、关键失败和失败步骤。
- results.json：同一份结果的完整元数据，便于后续汇总与比较。
- 退出码 0：全部通过；1：存在失败；2：案例格式、执行或写入错误；130：手动中断。
- 任何案例失败都会导致整批失败；关键案例的失败还会单独列出，不以平均分掩盖。
- 案例中的预期拒绝或预期超时，在错误编号和状态检查都吻合时属于通过。
- 一个案例失败后停止该案例剩余步骤，继续其他案例。

## 当前检查什么

| 案例编号 | 验证内容 |
|---|---|
| normal_two_turns | 两轮对话成功提交，消息数量正确 |
| duplicate_request | 同编号同内容只调用一次；同编号不同内容被拒绝 |
| timeout_rollback | 模拟超时保留先前消息；重复请求复用失败；新请求可恢复 |
| invalid_output_rollback | 空回复校验失败，不写入半轮消息 |
| context_budget_preflight | 上下文超限在模型调用前拒绝 |
| step_budget_rollback | 步骤预算不足明确停止且不提交消息 |
| request_budget | 请求记录达到上限后拒绝新请求 |
| draft_correction_withdrawal | 纠正后重新确认；旧草稿及依赖它的旧回复被排除；撤回和清空生效 |
| stale_draft_revision | 旧版本确认被拒绝，当前版本可确认 |
| clear_tombstone | 清空后旧请求无法恢复正文 |
| ended_session | 结束后拒绝新消息 |
| session_isolation | 不同会话隔离历史和请求去重 |
| wait_resume | 演示等待当前确认后完成 |
| wait_cancel | 等待时取消；后续可开始新请求 |

这些案例通过同一套 SessionService、AgentOrchestrator 和 DraftService 执行。
模拟模型故意把确认草稿带入回复，用来检查纠正后是否排除了依赖旧草稿的旧回复。
运行器的取消案例覆盖等待确认阶段；正在调用模型时取消、并发排队与迟到结果丢弃，继续由现有运行框架测试覆盖。

## 怎样添加自己的工程案例

案例集位于 [runtime_v1.json](../evaluation/cases/runtime_v1.json)。
可以复制为新文件并用 --suite 指定，保留旧案例版本。以下是最小例子：

~~~json
{
  "version": "engineering_v1",
  "synthetic": true,
  "id": "my_engineering_suite",
  "cases": [
    {
      "id": "one_turn",
      "critical": true,
      "steps": [
        {
          "action": "send",
          "content": "虚构测试：你好",
          "expect": {"messages": 2, "model_calls": 1, "phase": "COMPLETED"}
        }
      ]
    }
  ]
}
~~~

~~~powershell
.\.venv\Scripts\python.exe -B -m app.evaluation --suite .\evaluation\cases\my_suite.json
~~~

案例数据与报告位置可以分别通过 --suite 和 --output 指定。
当前仅提供离线模式，不提供切换真实模型的参数。

固定操作包括 send、new_session、create_draft、edit_draft、confirm_draft、reject_draft、
clear、end、demo、confirm_demo、cancel。案例不能执行脚本、导入代码或自定义工具。

- 每个案例默认有 main 会话；new_session 的 session 字段创建新别名，其他操作用 session 选择会话。
- send 的 request 别名用于复用请求编号；省略时生成新编号。编号作用域仍是当前会话。
- send 的 model 可选 normal、timeout、invalid；后二者用于模拟异常。
- input_contains / input_absent 检查本步骤实际发送给模拟模型的输入；本步骤没有调用模型时，相关检查会失败，避免误查上一次输入。
- 草稿操作用 draft 引用快照别名，默认 current；save_as 可以保存新快照并保留旧快照，以测试过期版本。
- create_draft / edit_draft 需要 title 与 items；确认和拒绝使用对应快照的版本与凭据。
- expected_error 是预期的工程错误编号，不填写表示预期成功。具体例子见默认案例集。
- expect 可检查消息数、累计模拟调用数、阶段、停止原因、会话状态、草稿数量/版本/状态，以及最后成功上下文的来源数量与排除数量。
- context_drafts、excluded_replies 和 has_context 指的是最后成功提交的上下文记录；失败步骤不会覆盖它。
- 草稿版本检查读取当前实际草稿，而非仅检查所引用的旧快照。
- 未使用的预期字段直接省略；明确填写 null、未知字段、错误类型和未知别名会被拒绝。

## 预算、记录与复现

案例文件最大 1 MB；每批最多 100 个案例，每案例最多 40 步。
单案例执行最多 3 秒，整批执行预算 60 秒。预算用尽会记录失败，不输出虚假的通过结果。
模拟模型等待超时设为 0.02 秒，专门用于测试超时分支，和真实聊天的超时配置相互独立。
每案例可配置 context_chars、steps、requests，默认值为 48000、8、500，并由 Schema 约束范围。

每案例单独创建内存存储，不读取正在运行的 API 或终端会话。
报告保留案例集版本、规范化案例 SHA256、app 源码 SHA256、运行器/提示词/上下文版本及 Python/Pydantic 环境版本。
相同案例与源码可以比较逻辑结果；耗时、时间戳和报告目录不会完全相同。

报告不复制案例正文、消息、草稿、模型回复、输入匹配词或异常正文；匹配检查只输出布尔结果。
案例编号和错误编号属于报告元数据，也请只使用虚构标识，不放个人信息。
导出先完成两个文件再将目录公布为正式报告，已有报告不会被覆盖。

## Harness 笔记的本轮迁移

开发前重读了原始 harness 笔记和工程约定。本轮迁移了：

- 固定执行顺序与明确结果：校验案例 → 隔离执行 → 检查结果 → 汇总报告。
- 调用前预算与有界执行：输入、步骤、请求与时间均有限制。
- 作废结果不能提交：通过超时、无效输出、清空和草稿纠正案例反复检查。
- 诊断与正文分离：报告只有工程结果，不把模型输出当作评分或执行权限。
