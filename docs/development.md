# 后续 Agent 模块开发步骤

适用于理解、澄清、策略选择、Mind Canvas、卡片、安全判断、记忆和外部模块集成。
每次新增模块先在本文件的模块记录中填写以下内容，沿用已有运行框架。

## 每次开发的顺序与完成条件

1. 需求与归属：写明该模块解决的问题、输入来源和需要谁确认的业务规则。
   完成条件：明确标记已确认规则与待评审草案，能给出一个输入输出例子。
2. 输入与结果：定义受控 Schema、空值含义、证据来源和用户纠正方式。
   完成条件：有效例子可通过校验；缺失/错误数据有明确处理，不补造事实。
3. 流程：列出进入条件、等待/确认点、成功和失败原因、取消与清空行为。
   完成条件：分支可对应到运行状态与明确结束原因，不由模型直接赋值。
4. 预算与权限：写明模型调用次数、超时、上下文限制和读取/写入/外部调用范围。
   完成条件：超限会停止，权限和确认由程序检查。
5. 实现：通过小接口注入依赖，输出完整验证后再提交；沿用同会话串行与请求去重。
   完成条件：正常、失败及取消后均能检查会话一致性。
6. 验证：覆盖该模块新增的正常、拒绝、格式错误、超时、重复、取消和纠正分支。
   不适用的分支标注原因，避免为凑数量写重复测试。
   完成条件：相关测试与项目回归通过，外部调用验证单独记录。
7. 交付：更新接口示例、提示词版本、运行说明和模块记录。
   完成条件：用户能从终端或 API 复现结果，未完成的业务规则有清楚说明。

### 已完成：通用草稿修改、版本与确认

目的：让用户能够修改并确认一份系统提出的草稿，为之后的 Mind Canvas 和卡片提供基础。
先采用现有 DemoDraft 的 title/items 示例，输入输出不绑定心理字段或对外 JSON Patch 格式。

预期验收：

1. 新建草稿获得编号和版本 1。
2. 按版本 1 修改，得到版本 2。
3. 再拿版本 1 提交修改或确认，被明确拒绝，版本 2 保持不变。
4. 用户确认版本 2；之后再次编辑时，需要针对新版本重新确认。
5. 结束会话后不再接受编辑；清空会话时移除草稿与内容缓存。
6. 同样的操作在终端与 API 中具有一致结果，测试不依赖真实模型或心理判断。

下一步在上下文组装模块中接通“用户纠正影响下一轮”。
需要单独验证保留的历史对话与当前有效草稿的区别，不能只改界面上的文字。

### 通用草稿版本管理 V0.1（已完成）

- 归属：Agent 内部工程；使用 title/items 通用示例，不冻结心理字段或对外画布契约。
- 输入输出：创建、编辑、确认和拒绝请求；操作编号、预期版本；确认绑定当前版本凭据。
- 状态：PROPOSED / CONFIRMED / REJECTED；有效修改和决定都递增版本，编辑撤销旧确认。
- 预算：共享会话操作记录上限和内容长度预算；本模块不调用模型。
- 数据：仅内存，清空会话同时移除草稿及缓存回复；会话结束后拒绝新修改。
- 验证计划：版本冲突、过期确认、并发编辑、操作去重、跨会话隔离、清空与终端演示。
- 范围：本轮仅管理草稿；草稿进入真实模型上下文属于后续模块。
验收结果：104 项回归通过，本地 API 联调通过。操作说明见 [草稿版本管理](草稿版本管理.md)。

### 上下文组装与来源记录 V0.1（已完成）

- 开发前已重读原始 harness 笔记的回合预检、作废清理、静态/动态指令与事件隔离章节。
- 输入：当前会话历史、当前确认草稿、历史回复的草稿依赖、本轮用户输入。
- 输出：模型消息快照与不含正文的来源清单；历史用户原话保留，依赖失效草稿的助手回复不再注入。
- 条件：只使用本会话状态为 CONFIRMED 且确认版本匹配的草稿；普通用户数据不进入 system 角色。
- 预算：包括指令、草稿块和最终消息的字符数，超限在模型调用前拒绝；不自动总结或截断。
- 提交：成功后记录来源及回复依赖，失败保留最后成功记录；清空同时删除来源和依赖。
- 验证计划：纠正、撤回、重复、隔离、预算、权限层级、失败与终端离线演示。
本轮验收：117 项回归通过，真实 DeepSeek 修正草稿联调通过。操作说明见 [上下文组装与来源记录](上下文组装与来源记录.md)。

### 批量评测运行器 V0.1（已完成）

- 归属：Agent 工程评测；心理质量标签、标准答案和风险判定待团队提供。
- 输入输出：受控 JSON 虚构案例集，固定操作和预期结果；输出 Markdown 与 JSON 元数据报告。
- 流程：先校验案例，再逐案例隔离运行；预期拒绝属于通过，断言失败单独记录，其他案例继续。
- 预算：限制案例数、步骤数、输入大小和单案例时间；默认模拟模型，真实模型调用数为零。
- 权限与数据：不读取现有会话，不导出消息、草稿正文或 Key；报告按用户约定保存到 Obsidian。
- 验证：正常对话、去重、失败不提交、草稿纠正、撤回、清空、会话隔离；另测坏案例、错误预期和报告脱敏。
- Harness 依据：开发前重读原笔记，迁移调用前检查、有界执行、明确结果和诊断与对话分离。
验收结果（2026-11-01）：14/14 默认案例通过，新增 27 项运行器检查，全项目 144 项测试通过；真实模型调用为零。终端入口为 .\dev.ps1 -Mode eval。说明见 [批量评测运行器](批量评测运行器.md)，正式报告已保存到本目录的评测报告。

### 可选会话保存与恢复 V0.1（已完成）

- 归属：Agent 本地工程存储；不提炼心理记忆、画像或改变团队业务字段。
- 输入输出：显式保存当前会话与预期版本；本地 SQLite 快照、元数据列表、恢复与按存档版本删除。
- 流程：不自动保存或恢复；拒绝运行中/清空中的保存；恢复不覆盖已加载会话，不重放模型调用；旧确认权限失效。
- 数据：保存已完成消息、草稿版本、回复来源依赖和请求指纹；不保存 Key、缓存回复副本、事件及确认凭据。
- 预算：快照最大 4 MiB、最多 1000 份存档、有限 SQLite 锁等待；结构/版本不符在修改内存前拒绝。
- 并发与删除：会话锁下生成一致快照；存档写入/删除使用乐观版本与数据库事务；清空当前会话和删除磁盘存档独立。
- 验证：重启恢复、纠正依赖、旧请求不重跑、过期凭据、结束状态、版本冲突、损坏文件、事务失败、隔离、显式删除与终端/API 演示。
- Harness 依据：开发前重读原笔记，沿用明确停止原因、作废记录、显式确认和诊断/正文隔离。
验收结果（2026-11-01）：新增 31 项存档测试，全项目 175 项测试通过；独立终端子进程重启恢复、终端一键演示与 14/14 原工程评测通过，未调用真实模型。说明见 [会话保存与恢复](会话保存与恢复.md)。
