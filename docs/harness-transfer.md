## 后续每个模块沿用的原则

1. 定义模块的有效输入、结构化结果和证据来源，再写实现。
2. 在程序内约定进入条件、等待条件、完成条件和结束原因。
3. 将模型调用与状态提交分开；先校验完整结果，再提交。
4. 为调用设置预算，并明确达到上限后的行为。
5. 为取消和用户纠正设计正常路径；重试和失败不损坏已完成记录。
6. 新模块沿用请求编号、运行编号和脱敏事件，测试通过同一模块接口调用。
7. 需要授权的外部调用、个人数据读取或保存，先经程序检查；确认绑定具体操作。
8. 记录验证覆盖和暂未接入的团队规则，按开发步骤逐项交付。

## 迁移范围

当前只实现工程运行机制。业务状态 INITIAL 与运行状态独立：
COMPLETED 表示一次聊天或演示执行结束，不表示已经完成心理理解或经过专业审核。

本轮没有添加任意脚本 hooks、shell 工具、插件加载、多代理或自动训练。
这些能力与当前独立开发目标没有直接关系。
上下文预算按字符计算，不能称为精确 token 预算；本轮超限时明确阻断，
没有自动压缩用户经历、事实或确认记录。将来若引入摘要，要单独验证信息保真与来源。
默认内存会话和诊断事件在进程结束后消失；显式保存的本地快照可恢复，没有自动转为长期记忆或公共案例。
