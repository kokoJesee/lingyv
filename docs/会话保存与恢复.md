# 可选会话保存与恢复 V0.1

现在可以主动保存会话，关闭程序后重新恢复。聊天默认仍只保存在内存。
只有 /save 或对应 API 保存请求会把当前快照写入本地 SQLite；后续聊天不会自动更新存档。

## 先看终端演示

在 VS Code 终端执行：

~~~powershell
cd <项目根目录>
.\dev.ps1 -Mode archive-demo
~~~

演示只使用虚构数据和模拟模型，依次检查主动保存、重新建立运行环境后恢复、
旧请求不重放、继续对话、更新存档、清空与删除。默认使用临时数据库，结束后清理，不写入你的正式存档。

也可执行 .\.venv\Scripts\python.exe -B -m app.cli --archive-demo。

## 自己保存并恢复一次

先打开离线聊天：

~~~powershell
.\.venv\Scripts\python.exe -B -m app.cli --offline
~~~

聊几轮后输入 /save，再输入 /archives。终端会显示完整存档编号、当前存档版本和消息数量。
退出程序，再运行同一聊天命令，输入 /restore 加上刚才的存档编号或唯一前缀，然后 /history 查看历史。
恢复不会调用模型；发送新的普通消息才开始新一轮。

| 命令 | 行为 |
|---|---|
| /save | 首次主动保存当前会话快照 |
| /save 存档版本 | 更新已有快照，版本从 /archives 获取 |
| /archives | 列出磁盘存档元数据，不显示正文 |
| /restore 存档编号前缀 | 恢复并切换到该会话；已加载的会话不覆盖 |
| /archive-delete 存档编号前缀 存档版本 | 删除磁盘中的指定版本存档 |
| /clear | 清空当前内存会话；磁盘存档保留 |
| /use 会话编号前缀 | 切换到当前进程已经加载的会话 |

存档版本在数据库中全局递增，可能跳号；不要自行假设下一版本是几。
同一会话的磁盘存档只保留最近一次主动保存的快照。
覆盖和删除都校验当前存档版本，旧客户端不能覆盖新存档，也不能删除“删除后重新保存”的新快照。

普通聊天可使用 .\dev.ps1 -Mode chat，以上命令相同。
已有终端需要退出后重新运行，才能载入新命令。

## 保存到哪里

默认路径：../data/session-archives.sqlite3。

启动聊天或只查看空存档列表不会创建数据库。第一次主动保存才创建目录与数据库。
API 和聊天默认指向同一个本地存档文件，但各自的内存会话独立；在一个进程保存的快照，可在另一个进程主动恢复。
终端可通过 --archive-db 指定单独的 SQLite 路径，便于演示或测试。

保存内容包括：

- 已完成的用户消息与助手回复。
- 草稿内容、当前版本、状态及已完成的用户确认版本。
- 历史助手回复依赖哪些草稿版本，保证纠正后继续排除旧回复。
- 已保存范围内的请求编号及指纹，恢复后用于阻止重复执行。
- 会话编号、创建时间、生命周期、业务状态及保存时的运行阶段。

不复制 .env、API Key、诊断事件、模型任务、确认凭据或缓存回复副本。
存档是本地明文 SQLite 文件；当前用于本机单用户开发，尚未实现账户认证或存档加密。
本轮未加入画像、记忆提炼、向量库或对个人对话的自动归档。

## 恢复后的行为

1. 保留会话编号，恢复修订号增加 1；已结束会话仍然保持结束。
2. 原流程若在等待确认或运行中，恢复为 CANCELLED，原因 restore_interrupted；其他阶段重置为 IDLE。
3. 旧运行编号和旧流程确认凭据不恢复。需要继续演示时重新开始流程。
4. 待确认草稿获得新的确认凭据；草稿版本和内容不变。已完成确认的草稿保持确认状态。
5. 旧消息请求、旧草稿操作编号变为 request_restored 记录，不返回旧缓存，也不重新执行。新操作使用新编号。
6. 保存过的来源依赖继续生效，防止用户纠正后旧回复被重新注入。
7. 最近调用的 context_manifest 不恢复；下一次成功对话会生成新的来源清单。
8. 已加载的会话不会被存档覆盖。切换请用 /use；恢复旧快照请在另一个运行进程中进行。

这是手动快照：最后一次保存之后新增或修改的内容，不会因退出程序而自动保存。
最后一次保存之后的请求编号也不在快照的跨重启去重范围内，不提供跨崩溃的“执行恰好一次”保证。

## 清空与删除的区别

- /clear 处理当前内存会话、草稿和缓存，不删除磁盘快照。
- 希望用空会话替换旧存档时，先 /clear，再 /save 加上当前存档版本。
- /archive-delete 删除磁盘快照，应用之后无法从该存档恢复；当前已经加载的内存会话仍保留。
- 若希望两处都移除，先清空内存，再按版本删除磁盘存档。
- 删除后不自动重新保存；用户再次执行 /save 才可能创建新快照。

SQLite 删除启用 secure_delete；数据库事务完成后才返回成功。删除指的是当前数据库中的存档。

## API

可在 http://127.0.0.1:8000/docs 中直接操作。

| 方法与路径 | 输入与行为 |
|---|---|
| POST /sessions/{session_id}/archive | expected_revision 必填；首次保存省略 expected_archive_version，更新时填写当前存档版本 |
| GET /archives | 返回存档编号、存档版本、会话修订号、保存时间、状态及数量 |
| POST /archives/{archive_id}/restore | 主动恢复到当前进程；不覆盖已存在会话 |
| DELETE /archives/{archive_id}?expected_version=版本 | 按版本删除，成功返回 204 |

首次保存示例（expected_revision 应取当前会话实际值）：

~~~json
{"expected_revision": 2}
~~~

更新时同时传入 expected_archive_version。会话版本与存档版本是两个独立的值：
前者确保保存的是刚查看的会话状态，后者防止覆盖其他进程更新的存档。

主要错误：

| 错误编号 | 含义 |
|---|---|
| archive_session_busy | 模型调用或清空正在进行，完成后再保存 |
| stale_revision | 会话修订号变化 |
| archive_version_conflict | 存档版本变化，刷新后再操作 |
| session_already_loaded | 当前进程已经加载该会话 |
| archive_not_found | 没有该存档或已删除 |
| archive_invalid | 快照损坏、缺少来源依赖或数据不一致 |
| archive_version_unsupported | 数据库或快照版本不受支持，不自动猜测迁移 |
| archive_too_large / archive_limit_exceeded | 超过快照或存档数量预算 |
| archive_storage_error | 本地读写失败或锁等待超时 |
| request_restored | 恢复的旧编号被阻止再次执行 |

## 一致性与预算

同一会话在锁内取得一致快照，运行中或生命周期变更中的保存会被拒绝。
写入、更新、删除均使用事务和版本检查；恢复的元数据与正文在同一个读事务中读取。
磁盘调用在工作线程中完成，SQLite 锁等待上限为 1 秒。
请求取消时会等已提交执行的磁盘操作收尾，再释放会话锁，因此操作可能已经完成；重新查看 /archives 可确认结果。

快照格式与数据库版本均为 1。快照最大 4 MiB，最多 1000 份存档；
每快照最多 2000 条消息、1000 份草稿和 10000 条操作指纹。
消息必须是完整成对回合；草稿归属、确认版本、回复来源和指纹会在恢复前校验。
不符合要求时不修改当前内存，也不覆盖已有存档。
